# KetPlus performance baseline — 2026-09-09

## Environment

- Revision: `9159294`
- Build: Release, AppleClang 21.0.0
- KetPlus: 0.1.0
- Qt: 6.11.1
- OS: macOS 26.2, Darwin 25.2.0
- Hardware: Apple M1 Pro, 10 CPU cores, 32 GiB RAM
- Application bundle: 4.0 MiB before Qt deployment

The machine was on normal desktop power settings. Editor-engine measurements
used Qt's offscreen backend. Native startup measurements launched a real macOS
window and therefore have significantly more variance.

## Editor engine

| Workload | Median | Min | Max | Throughput |
| --- | ---: | ---: | ---: | ---: |

| Set 10 MiB text | 6.228 ms | 5.799 ms | 11.350 ms | 1,605.5 MiB/s |
| Set 50 MiB text | 33.331 ms | 29.322 ms | 78.039 ms | 1,500.1 MiB/s |

Replace All changed 145,636 whole-word matches and remained one Undo operation.

## Native application startup

turn after `show()`. It includes synchronous file loading and lexing, but not a
verified first-painted frame. Each case used 7 runs.

## Steady-state memory

One native sample was taken three seconds after opening each document. macOS
physical footprint is the more useful application-cost metric; RSS also counts
many shared mappings.

| Workload | RSS | Physical footprint |
| --- | ---: | ---: |
| Empty document | 123.3 MiB | 51 MiB |
| Open 1 MiB text | 128.6 MiB | 56 MiB |
| Open 10 MiB text | 173.4 MiB | 93 MiB |
| Open 50 MiB text | 247.5 MiB | 262 MiB |
| Open 10 MiB C++ with lexer | 162.0 MiB | 97 MiB |

## Interpretation

- Core editing throughput is strong: loading content into the editor is around
  1.5–1.8 GiB/s and a full 10 MiB search is about 1.5 ms.
- Replacing 145,636 matches in a 10 MiB document takes about 181 ms, fast enough
  for interactive use.
- Empty native startup is currently dominated by Qt, font, and WindowServer
  initialization and is noisy. A future target should be a repeatable median
  below 300 ms on this machine.
- Large-file memory is the main concern. A 50 MiB text file reaches a 262 MiB
  steady physical footprint and a 323 MiB startup peak. The document model,
  temporary load buffers, Scintilla storage, and styling metadata should be
  profiled before calling the editor large-file optimized.
- C++ lexing adds roughly 322 ms and 3.5 MiB of peak footprint over the 10 MiB
  plain-text case.
- The 4 MiB bundle is not a distributable size because Qt frameworks have not
  yet been embedded with `macdeployqt`.
